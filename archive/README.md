# Archive — superseded work

Kept for reference, not part of the submission.

## `streamlit-app/`

The original dashboard, built with Streamlit for a synthetic schema (52 weeks, 3
markets, USD) before the real extract arrived. Predates cross-filtering. Superseded
first by `streamlit-app-2/`, then by the static site.

## `streamlit-app-2/`

The second Streamlit dashboard, rebuilt for the real extract (8 weeks, 8 markets,
AED) with Power BI-style click-to-cross-filter: click a bar, a line, a stacked
segment or a heatmap cell and every other chart on the page re-runs on that slice,
including the underlying analysis (ROI, market scorecards, reallocation) — not just
which rows are visually highlighted. `state.py` owned the filter state; `charts.py`
documented two Streamlit/Plotly quirks that silently swallow clicks if you don't
know about them (bar and heatmap traces don't natively emit click selections — only
scatter does — so bars carried an invisible scatter "hit layer"; and passing
`config=` to `st.plotly_chart` disables selection entirely). Chrome was stripped and
replaced with the same Samsung design system as the static site.

Retired once the static HTML site (`site/`, generated by `src/build_site.py`)
reached the same click-to-cross-filter capability — via `assets/app_filter.js` and
`src/serve.py`'s filtered-table API — without a Python process, a charting library,
or a web framework, and without maintaining two analysis-consuming surfaces in
parallel.

To run it anyway:

```bash
pip install streamlit==1.41.1 plotly==5.24.1
cd archive/streamlit-app-2
streamlit run Home.py          # run from here, so it picks up .streamlit/config.toml
```

Those two packages were removed from `requirements.txt` when the site replaced it,
so they need installing separately.

## `powerbi/`

The retired Power BI project: a star-schema PBIP/TMDL model with 40 DAX measures,
generated by `build_powerbi.py` from the same `data/processed/*.parquet` tables
everything else reads. Kept as evidence of the approach — a working star schema with
measures restated in DAX, not just a wireframe — but not maintained alongside the
current pipeline, since the static site is now the only dashboard and doesn't need
it as an input.

To regenerate it against current data: copy `archive/powerbi/build_powerbi.py` back
to `src/`, add it back as a step in `src/run_all.py`, and open
`archive/powerbi/SamsungMENA.pbip` in Power BI Desktop.

## `streamlit-tests/`

Headless `AppTest` coverage for `streamlit-app-2/`: every page, and the click →
filter → recompute → render path for the cross-filter engine, run without a
browser. It caught real bugs during development that a visual pass missed: two
peer-comparison tables (`market_scorecard`, `reallocation`) that broke when
filtered down to a group smaller than the peer set they compare against, and a
top-line KPI strip that silently ignored a channel filter because it summed from a
table with no channel column. Retired alongside `streamlit-app-2/` — there is no
equivalent suite for the static site; `src/validate_site.py` fills the same role
structurally (broken links, empty charts, NaN/USD leaks) but doesn't simulate
clicks.

## `smoke_test_app.py`

Headless renderer for `streamlit-app/`'s pages, predating `streamlit-tests/`. The
equivalent for the static site is `src/validate_site.py`, which is stricter — it
checks that every page was generated, that no chart came out empty, that every
internal link resolves, and that the synthetic-data disclosure is present on each
page.
