# Power BI — report build spec

The **semantic model is complete**: 19 tables in a star schema, 18 relationships and
40 DAX measures, generated by `src/build_powerbi.py`. Open `SamsungMENA.pbip` in
Power BI Desktop and the model, relationships and measures are already there — you
are only placing visuals.

**Report visuals are deliberately not generated.** Power BI's report JSON is
version-specific and undocumented; a malformed one stops Desktop opening the project
at all, which is worse than an empty report. The model is the part that takes hours;
the visuals below are about 45 minutes of drag-and-drop.

---

## Before you start

1. Open `SamsungMENA.pbip` in Power BI Desktop.
2. **Transform data → Manage Parameters → `DataFolder`** — confirm it points at your
   `data/processed/powerbi/` folder. It is written as an absolute path at generation
   time, so it only needs changing if you move the repo.
3. Refresh. All 19 tables should load.
4. Model view: relationships should be many-to-one, single direction, fact → dim.

Moving the repo? Re-run `python src/build_powerbi.py` rather than editing paths by
hand. Regeneration replaces only `SamsungMENA.SemanticModel/`,
`SamsungMENA.Report/` and `SamsungMENA.pbip` — this spec and any saved `.pbix` are
left untouched.

## Two things to know about this model

**Currency is AED.** Every money measure is formatted with an AED suffix. There is
no USD anywhere and none should be introduced.

**There is no date table, by design.** The source carries an integer week 1–8 and no
calendar dates. DAX time-intelligence functions (`DATEADD`, `SAMEPERIODLASTYEAR`,
`TOTALYTD`) all require a real date dimension and **will not work here** — the
prior-week measures use week-offset arithmetic instead:

```dax
Sales PW =
VAR w = SELECTEDVALUE(dim_week[week])
RETURN CALCULATE([Sales], ALL(dim_week), dim_week[week] = w - 1)
```

Marking a fabricated date table as a date table would unlock those functions and
simultaneously let seasonality claims into a dataset that cannot support them. Don't.

## Page 1 — Overview

Slicers across the top: `dim_market[market]`, `dim_week[week]`, `dim_product[product]`.

| Visual | Type | Fields |
|---|---|---|
| KPI row | 6 × Card | `[Sales]`, `[Media Spend]`, `[MER]`, `[Spend as % of Sales]`, `[Earned Share of Sales]`, `[TV Share of Spend]` |
| Channel ROAS | Bar | Axis `dim_channel[channel]`, Value `channel_efficiency[roas]` |
| Spend vs sales share | Clustered bar | Axis `dim_channel[channel]`, Values `share_of_spend`, `share_of_sales` |
| Weekly sales | Line | Axis `dim_week[week]`, Value `[Sales]` |
| Weekly spend | Line | Axis `dim_week[week]`, Value `[Media Spend]` |

**Do not put sales and spend on one chart with a secondary axis.** The alignment of
two y-scales is arbitrary, so the chart invents a correlation the data does not
contain. Two charts side by side is the correct form.

**Add a text box stating the TV measurement gap** near the KPI row. A reader who
sorts by ROAS and sees TV blank must be told why, or they will read it as zero.

## Page 2 — Channels

| Visual | Type | Fields |
|---|---|---|
| Efficiency table | Table | `channel_efficiency`: channel, spend_aed, sales_aed, roas, roi_gross_margin, cpa_aed, payback |
| Reallocation | Bar | Axis `reallocation[channel]`, Value `spend_change_aed`. Conditional format: negative `#d03b3b`, positive `#2f4bd4` |
| Panel model | Error bar / scatter | `panel_model`: coefficient with ci_low and ci_high |
| Funnel | Funnel | `[Impressions]`, `[Clicks]`, `[Conversions]` |

Conditional-format `roi_gross_margin`: below `1.0` red, at or above green. That
column, not `roas`, is the one a budget decision turns on.

If the error-bar visual is unavailable, use a table showing coefficient, ci_low,
ci_high and p_value — **do not show the coefficient alone.** The interval is the
finding: most channels cannot be distinguished from zero on 8 weeks.

## Page 3 — Markets & Products

| Visual | Type | Fields |
|---|---|---|
| MER by market | Bar | Axis `dim_market[market]`, Value `[MER]` |
| vs peer median | Bar | Axis `dim_market[market]`, Value `[MER vs Peer Median]`, diverging from 0 |
| Sales gap | Bar | `market_scorecard[sales_gap_vs_peer_aed]` |
| Product summary | Table | `product_summary`: product, spend_aed, sales_aed, roas, support_index |
| Product × channel | Matrix | Rows `dim_product[product]`, Columns `dim_channel[channel]`, Values `product_channel[roas_index_vs_product]`, background colour scale |

Use a **single-hue** colour scale on the matrix (light → dark). A rainbow scale
implies categories where the data has magnitude.

## Page 4 — Influencers

| Visual | Type | Fields |
|---|---|---|
| CPA ranking | Bar | Axis `influencer_scorecard[influencer]`, Value `cpa_aed` |
| Engagement vs CPA | Scatter | X `engagement_rate`, Y `cpa_aed`, Size `spend_aed`, Legend `flag` |
| Scorecard | Table | influencer, market, followers, engagement_rate, spend_aed, conversions, cpa_aed, roas, recommended_action |
| Margin check | Card | `[Influencer ROI on Margin]` |

Keep the scatter legend to two or three classes — on a scatter every pair of points
sits adjacent, and more stop being distinguishable under colour-vision deficiency.

## Page 5 — Brand & Early Warning

| Visual | Type | Fields |
|---|---|---|
| Awareness by market | Bar | `[Brand Awareness]` by `dim_market[market]` |
| SOV gap | Bar | `[SOV Gap]` by `dim_market[market]` |
| Alert feed | Table | `alerts`: severity, category, entity, rule, detail, owner, action |
| Alert counts | Card | `[Open Alerts]`, `[Critical Alerts]` |

Conditional-format severity: critical `#d03b3b`, high `#ec835a`, medium `#fab219`.
**Keep the severity word visible** — colour alone is not readable for every viewer.

**Add a text box on the brand visuals** noting the metrics are an indicative index
averaged from row-level values, not a measured tracker.

## The 40 measures

All on `fact_market_week`, matching the definitions used by the HTML dashboard and
the AI assistant so a figure cannot disagree between surfaces.

**Volume** — Sales, Media Spend, Conversions, Impressions, Clicks, Sessions, Paid
Spend, Earned Sales, TV Spend, TV GRPs

**Efficiency** — MER, CPA, AOV, CPM, CPC, CTR, Cost per GRP, Earned Share of Sales,
TV Share of Spend, Spend as % of Sales

**Margin** — Gross Margin Rate (0.22, the one number to change when Finance
confirms), ROI on Margin

**Brand** — Brand Awareness, Purchase Intent, Sentiment, Share of Voice, Competitor
SOV, SOV Gap

**Week-over-week** — Sales PW, Sales WoW %, Spend PW, Spend WoW % *(week-offset, not
`DATEADD`)*

**Peer benchmarking** — Peer Median MER, MER vs Peer Median

**Influencer** — Influencer Fees, Influencer Conversions, Influencer CPA, Influencer
ROI on Margin

**Alerts** — Open Alerts, Critical Alerts
